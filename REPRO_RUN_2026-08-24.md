## 4. Known traps to watch for

- **Disk — projected to fit, but not by much.** Measured at 11:04, one hour in:
  steady-state burn **26 GB/h**, work dir 35 GB, `SNIPPY_SCATTER` 313/4,704
  (6.7%). Extrapolating Snippy alone gives **~10 more hours and ~270 GB**,
  against **371 GB free**, so it should land with roughly 60–100 GB to spare
  once Gubbins and IQ-TREE are added. That margin is real but thin, and the
  estimate assumes the burn rate does not rise — Gubbins writes per-unit
  recombination predictions and joint ancestral sequences across 172
  replicon-units, so it may.

  The watchdog SIGTERMs Nextflow below 40 GB so the filesystem cannot fill.
  Nextflow then leaves a resumable cache rather than dying arbitrarily, so a
  watchdog stop is **not** a reproducibility failure.

  **If the watchdog fires, do NOT relocate the work dir** — Nextflow's cache
  stores absolute paths and moving it breaks `-resume`. Free space on `/`
  instead, then resume with the work dir where it is:

  ```bash
  cd /home/phemarajata/wf-assembly-snps-mod-79ab645 && nextflow run . -resume -work-dir /home/phemarajata/Downloads/snp-mod-local-working/REPRO_2026-08-24_work
  ```

  **`TB1` is attached** (`/media/phemarajata/TB1`, ext4, **630 GB free** of
  916 GB) and is the place to move things to. Candidates on `/`, largest first:
  `v4c_local` 21 GB, `L1_out` 15 GB (an *older* run — not `L1v4c_out`),
  `a100_stage` 6.4 GB, `a100_v4c_partition` 6.2 GB. **Never move `L1v4c_out`
  (17 GB)** — it is the reported run's output and the source of the frozen
  tables that the diff in §5 compares against.
- **The zero-seed Gubbins/RAxML failure.** Unseeded `randint(0, 10000)` hits 0
  about 1 in 10,001, and there is roughly a **16% chance of silently losing a
  unit** across a full run. If `GUBBINS_CLUSTER` finishes at 171 rather than
  172, this is the first thing to check — it is a known pipeline bug, not a
  reproducibility finding.
- **The `errorStrategy` fall-through.** Every heavy process in
  `curated_L1_overrides.config` uses
  `(exitStatus in [...] && attempt <= 2) ? 'retry' : 'ignore'`. A task failing
  on attempt 3 is **dropped, not failed**, and the run still reports success.
  **Always check the per-process counts above rather than the exit code.**
- **Don't start a second Gubbins run concurrently** — Gubbins writes scratch to
  the CWD, not to `--prefix`.
